### 読み出しについての注記

Stonkfly は**左右 DNp20 の差**（回転の癖）を売買に読み替えている。
逃避回路（LC4 / LPLC2 → DNp01）は使っていない。

ドパバエは Stonkfly と**別の読み出しを採る**（[`DESIGN_MEMO.md`](DESIGN_MEMO.md) 3.3 節）。
接近／回避の回路をその意味のまま使うほうが、読み替えの恣意性が小さいと判断したためである。
**これは設計者の選択であり、検証されていない。** Stonkfly 自身が
「回転の癖が買い癖になりうる。それを市場の洞察と解釈するな」と警告しているのと同じ危険が、
接近／回避の読み出しにもある。Phase 4 の評価で測る対象はここである。

### 2.1 エッジ数は閾値で変わる

同じ MaleCNS でも、シナプス数の閾値で桁が動く。

| 閾値       | エッジ数 | 出どころ          |
| ---------- | -------- | ----------------- |
| 5 以上     | 6.2M     | Codex の既定表示  |
| 3 以上     | 10.5M    | nfly              |
| 閾値なし   | 25.6M    | Stonkfly          |

**閾値はモデルの選択であり、データの性質ではない。** メモリと挙動の両方に効くので、
決めたら `agent.yaml` に置き、判断ログの指紋に含める。

### 2.2 ヒスタミンが FlyWire の予測列にない（重要）

光受容細胞はヒスタミン作動性である。Stonkfly はヒスタミンを抑制性として符号を付けている。
FlyWire の伝達物質予測にヒスタミンの列がないなら、**網膜出力の符号を別途
細胞型から与える必要がある。** FlyWire を選ぶ場合に確実に発生する追加作業。

### 2.3 キノコ体だけの切り出しは成立しない

ドパバエの経路は「網膜 → 視葉 → 中枢脳 → KC → MBON → 下行性」である。
キノコ体だけを切り出すと、**視覚入力が KC に届く経路が消える。**

[`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) の「全脳を回すか、キノコ体まわりだけ
切り出すかは性能を測ってから決める」は、この点で書き直しが要る。現実的な選択肢は
全 CNS か、視覚から下行性までを残す切りかたのいずれかになる。

### 2.4 FAFB の左右反転（FlyWire を選ぶ場合の落とし穴）

画像とセグメンテーションは左右が反転したままで、注釈側だけ修正済みとされる。
左右の視野マッピングを作るときに踏むと、**エラーにならずに間違える。**

### 3.4 NC の定義と、本プロジェクトの当てはめ

CC BY-NC 4.0 Section 1(i) の定義は次の 1 文で完結しており、
legalcode 中にこれ以上の例示も判定手順も存在しない。

> NonCommercial means not primarily intended for or directed towards commercial
> advantage or monetary compensation.

条文から言える事実は 2 つ。判定基準は用途の**主目的**（`primarily`）であって
利用者の属性ではない。そして「収益」「個人」「研究目的」「模擬」といった語による
細分化は条文にない。

したがって、**模擬売買のみで実資金を動かさず収益も発生しない本プロジェクトが
NC に触れるかは、条文だけからは一義に決まらない。** ここで法的判断はしない。

**この不確実性は MaleCNS を選べば発生しない。** CC BY 4.0 の legalcode には
NonCommercial の定義自体が存在せず、Section 2(a)(1) にも用途の限定がない。

### 3.5 派生物（Adapted Material）の扱い

ShareAlike 条項は**両ライセンスとも存在しない。** Section 3 は Attribution のみで、
派生物に同一ライセンスを課す条項はない。唯一の制約は Section 3(a)(4)
（派生物に適用する条件が、受領者の本ライセンス遵守を妨げてはならない）。

重み配列に効くのは Section 4（Sui Generis Database Rights）である。
コネクトームはデータベースなのでこの節が働く。CC BY 4.0 Section 4(b) は、
データベース内容の全部または相当部分を自らのデータベースに含めた場合、
そのデータベース（個々の内容ではない）が Adapted Material になると定める。
4(c) は、内容の全部または相当部分を Share する場合に Section 3(a) の条件に
従うことを求める。CC BY-NC 4.0 の Section 4 も同一構造で、
4(a) に `for NonCommercial purposes only` が付くだけである。

**シミュレーションの発火数記録が Adapted Material にあたるかは、条文に判断材料が
ない。** Section 1(a) の `derived from or based upon` と
`in a manner requiring permission` の当てはめが要るが、条文はこの種の出力について
何も述べていない。Janelia / FlyWire いずれの一次資料にも記述はなかった。

### 3.6 再配布の方針（本リポジトリの既定）

[`REPOSITORY_PLAN.md`](REPOSITORY_PLAN.md) の「扱わないもの」8 のとおり、
**配線図データはリポジトリに含めない。** 取得 URL とチェックサムだけを置く。

この方針はライセンスの都合だけでなく、**再現性のためでもある。** Stonkfly は
SHA-256 でソースを検証し、コンパイル済みの配列もコミット済みのロックと突き合わせている。
同じ形を採る。

**URL やチェックサムの公開を制限する記述は、確認したどの資料にも見つからなかった**
（CC BY 4.0 / CC BY-NC 4.0 の legalcode 全節、`male-cns.janelia.org` の各ページ、
HHMI ToU、FlyWire の ToS / Principles / guidelines、Zenodo 両レコード）。
**これは「該当する記述が見つからなかった」という事実であって、
「問題ない」という確認ではない。**

周辺で記録しておくべき点が 2 つある。

- FlyWire ToS 第5項は、サイトに過負荷をかける使い方をアカウント停止理由に
  挙げている。ダウンロードの自動化に関係しうる
- **Codex 由来のダウンロード URL は API トークンを含む形式である**
  （`?data_product=...&dataset=fafb&api_token=...`）。公開リポジトリに置けば
  秘密情報が漏れる（[`../CLAUDE.md`](../CLAUDE.md)「API キー・シークレット・
  プロファイル名は、ログにも記憶にも残さない」）。`gs://` と Zenodo の URL は
  トークン不要

### 3.7 表示（Attribution）

要求項目は両ライセンスの Section 3(a)(1) で完全に同一である。
Share する場合、権利者が付していれば、作成者の表示・著作権表示・
本ライセンスへの参照・保証否認への参照・作品への URI を保持し、
改変したならその旨を示し、本ライセンスの下にあることを示す。

書く場所は Section 3(a)(2) が「媒体・手段・文脈に応じた合理的な方法」で
足りるとし、必要情報を含むリソースへの URI を提供する方法を例示している。
README / THIRD_PARTY.md / NOTICE のどこに書くかを条文は区別していない。

**公式の表示テンプレートは、MaleCNS / FlyWire いずれについても存在しなかった。**

前提として、3(a) の義務は `If You Share the Licensed Material` にかかる。
データ本体を配布しない構成（3.6）では、**Share にあたる行為があるかどうかが
先に決まらないと、この節が働くかも決まらない。**

| `zhengxuyu/nfly`                    | MaleCNS v1.0 | **ドパバエに最も近い**（画像入力＋下行性読み出し）。ただしレート型でスパイクなし、可塑性なし。MIT |
| `TuragaLab/flyvis`                  | 視葉         | 幾何学的な六方格子サンプリング                   |

Stonkfly の LIF パラメータは Shiu ら (2024) の再利用とされる
（静止 −52 mV、閾値 −45 mV、膜 20 ms、シナプス 5 ms、不応期 2.2 ms、遅延 1.8 ms、
接触あたり 0.275 mV、刻み 0.1 ms。Stonkfly は KC の静止電位だけ −60 mV に変更）。

### 5.1 光受容細胞へのマッピングは 2 系統

| 方式                           | 中身                                                   |
| ------------------------------ | ------------------------------------------------------ |
| 幾何学的な六方格子（flyvis）   | 画像に六方配列を置き、周辺画素の平均輝度を与える       |
| カラム注釈から座標（nfly / Stonkfly） | `assignedOlHex` を網膜座標として使い、標的のシナプス重み付き座標に配置 |

チャート画像は人工的な二次元画像なので、後者が自然に見える。
ただし**両方式とも、実装者自身が生体との対応に強い留保を付けている。**

## 7. 評価（Phase 4）へ持ち込む論点

調査で出た交絡要因は、評価の設計に入れておく価値がある。

- **表示感度**：Stonkfly は暗い背景では KC がほぼ発火せず、明るい背景へ変えている。
  **背景と配色は交絡要因である。** 同じハエで配色だけ違う腕を置けば測れる
- **文字**：ペア名と気配の数字は、ハエには読めないが画素としては入力される。
  価格が変われば模様も変わるので、意味のない変動が混ざっている可能性がある。
  「文字なしの腕」と比べれば測れる（2026-09-15 の実データを見て出た論点。
  [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) Phase 2 後半）
- 上の 2 つを測るには、`scripts/make_arm.py` が `fly.vision`（配色と `show`）も
  差し替えられる必要がある。いまは方向の出どころと置き場所しか変えない
- **読み替えそのものも腕にできる**（Phase 2 後半で実装した `fly.retina`）。
  R8 に渡す代理値（`r8_channel` の青／緑／平均）、格子を画像へ置く向き
  （`flip_x` / `flip_y`）、1 個が見る範囲（`field_px`）は、いずれも設計者が
  決めたものであって検証されていない。腕として比べれば、どれだけ効くかが測れる
- **静止発火率**：光受容細胞は抑制性しか出さないため、全ニューロンが静止していると
  「光が当たる」＝「脱抑制」として現れる。静止発火率の置きかたで挙動が変わりうる
- **閾値**：シナプス数の閾値も、腕として比べられる
