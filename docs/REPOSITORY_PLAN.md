# Dopabae Repository Plan

> **この文書の役割**：本リポジトリで**実装してよい範囲**の定義。
> **実装範囲の唯一の正**：実装してよいかの判断は本書に従う。
> [`DESIGN_MEMO.md`](DESIGN_MEMO.md) や参考にした外部プロジェクトに書かれていても、
> 本書の「扱わないもの」にあるものは実装しない。
> **開発の順序は本書に書かない**（[`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) を参照）。

## このリポジトリの位置づけ

このリポジトリは、AIエージェントファームにおける
2体目の試験エージェント「ドパバエ」（Dopabae）の実装を担当する。

1体目のナンピノニクス（`tjackiet/ai-agent-farm-nampinonychus`）を型にした
**別個体**であり、ショウジョウバエのコネクトームを LIF ニューロンで動かし、
15分足のチャート画像を「目」に見せて、その反応を売買の**方向**にだけ使う。
数量・価格・上限・諦めは決定的コード（檻）が担う。**現物のみ**を扱う。

対象は**この個体1体ぶん**である。汎用化・共通化は本リポジトリの目的ではない。
ナンピノニクス側のリポジトリは**参照するだけで、変更しない**。

## このリポジトリでは扱わないもの

1. 他のAIエージェントの実装（ナンピノニクスを含む。参照のみ）
2. 複数エージェント共通の汎用基盤
3. エージェント全体を集約する公開ダッシュボード
4. コミュニティ投稿システム
5. 3Dキャラクター生成
6. **実資金による取引**
7. **Stonkfly の live モード**（Coinbase Advanced への発注、取引所 API キー、
   AgentKit の ActionProvider）。参照するのは README と `docs/model.md` の
   モデル部分（LIF パラメータ、入力マッピング、読み出し、報酬・可塑性）だけ
8. コネクトームのデータ配布物そのもの（配線図データはリポジトリに含めない。
   データソースとライセンスは**要確認**であり、本書では選定しない）
9. 信用取引・レバレッジ（売りから入る建玉）。`bitbank paper` が現物のみのため。
   CLI への改善要望は Issue として出す

また、`bitbank-lab-cli` および `bitbank-lab-mcp` 本体の実装も扱わない。
本リポジトリは CLI を**利用する側**であり、上流への改善は
Issue・Pull Request として提案する。

`bitbank-lab-mcp` は本リポジトリでは利用しない。

## 範囲の判断に迷ったとき

「扱うもの」にも「扱わないもの」にも当てはまらない依頼は、
勝手に判断せず、次の手順で確認する。

1. この個体1体を動かす・評価するために必要か
2. 他のエージェントにも使える汎用機能になっていないか
3. ハエ脳に「方向を決める」以外の権利（数量・価格・上限・諦め）を渡していないか
4. **1 が「はい」かつ 2・3 が「いいえ」のときだけ扱う。** それ以外は指示を仰ぐ。

判断がつかない場合は実装せず、範囲の確認を求める。

## 前提と制約

本リポジトリの実装は、以下を常に満たす。詳細は [`../CLAUDE.md`](../CLAUDE.md) を参照。

- 実資金による取引を行わない（ペーパートレードのみ）
- 数値パラメータの正は `agent.yaml`
- ハエ脳が決めるのは方向だけ。数量・価格・上限・諦めは `agent.yaml` の値で檻が決める
- 現物のみ。売りから入る建玉は作らない
- 学習で変わるのはシナプス重みだけ。読み出しの閾値・対象ニューロン・報酬の閾値は
  `agent.yaml` に置き、ハエが書き換えない
- `personality.md` と `risk-policy.md` が矛盾する場合は `risk-policy.md` が勝つ
- 判断できないときは HOLD（シミュレーション失敗・入力欠損を含む）
