# 設計メモ — ドパバエ（Dopabae）

> **この文書の役割**：本リポジトリで開発する個体（ナンピノニクスを型にした
> **別個体**）の設計メモ。**作業指示ではない。** 本リポジトリの実装範囲は
> [`REPOSITORY_PLAN.md`](REPOSITORY_PLAN.md) にのみ定義され、
> 実装の順序は [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) が正である。
> 本書はナンピノニクスのリポジトリ
> （`tjackiet/ai-agent-farm-nampinonychus` の `docs/FLY_AGENT_DESIGN_MEMO.md`）
> から持ち込んだ下書きを、2026-09-15 の決定（**ハエが方向を決め、コードは檻**、
> **現物のみ**、個体名は**ドパバエ**）に合わせて書き直したものである。
> 持ち込み元は参照のみで変更しない。元の版（拒否権だけの設計）はそちらに残る。
> 本書に書かれていても、`REPOSITORY_PLAN.md` の「扱わないもの」にあるものは実装しない。
> 参考にした外部プロジェクト：
> [nftechie/stonkfly](https://github.com/nftechie/stonkfly)（MaleCNS v1.0 を使った試み）。

## 1. 何をする個体か

ショウジョウバエのコネクトーム（配線図）を LIF ニューロンで動かし、
**15分足のチャート画像を「目」に見せ**、その反応を売買の方向に使う。

ハエが決めるのは**方向だけ**（近づく／逃げる／どちらでもない）。
何を買うか・いくら買うか・どこで諦めるかは決定的コード（檻）が担い、
ハエの反応がどうであれ最悪ケース（建玉の上限、現金の下限、撤退の線）は変わらない。

拒否権だけを渡す設計（持ち込み元の版）は採らなかった。決定的コードが決めた買いを
止めるだけでは、ハエは設計者のロジックに付いたノイズ源にしかならず、
エージェントである理由がない。ハエの脳が実際に持っている判断の回路
（近づく／逃げる）を、その本来の意味のまま使う。

これは「ハエの脳を取引システムに繋ぐ実験」であり、
**儲かることを目的にしない。** 目的は次の2つ。

1. 重み固定のハエの反応が、ランダムと区別できる偏りを持つか観察する
2. 報酬学習（ドーパミンによる可塑性）を足したとき、挙動がどう変わるか観察する

## 2. ナンピノニクスから持ち出すもの・変えるもの

| 項目               | ナンピノニクス                         | ドパバエ                                            |
| ------------------ | -------------------------------------- | --------------------------------------------------- |
| 発注・市場データ   | `bitbank-lab-cli`（paper）             | **同じ**（現物のみ）                                |
| 実行間隔           | 15分                                   | **同じ**                                            |
| 判断の主体         | 決定的コード（`decide.py`）            | **ハエ**。決定的コードは檻だけ                      |
| LLM の関与         | 拒否権（`veto.py`）と記録の言語化      | 記録の言語化だけ。**売買には関与しない**            |
| 入る条件           | アンカーからの下落率                   | ハエが `APPROACH` と答えた                          |
| 出る条件           | 利確ライン、時間切れ                   | ハエが `AVOID` と答えた、または檻の諦め（時間切れ・ドローダウン） |
| 見るもの           | 数値                                   | 画像                                                |
| 学習               | なし                                   | ドーパミンで KC→MBON の重みが変わる                 |
| 呼べないときの扱い | `veto.on_failure: hold`                | `direction.on_failure: hold`（シミュレーション失敗・入力欠損は HOLD） |
| 数値の正           | `agent.yaml`                           | **同じ**。学習で動くのはシナプス重みのみ            |
| 実取引             | しない                                 | **しない**（Stonkfly の live モードは持ち込まない） |

CLAUDE.md の不変ルール（ペーパーのみ、迷ったら HOLD、値を自分で書き換えない、
観測していない値を書かない、秘密情報を残さない）は**そのまま引き継ぐ**。
リスク値（建玉上限・現金比率・ドローダウン停止・強制手仕舞い）は
ナンピノニクスと同じ値から始める。

## 3. 構成

```
15分足 (bitbank candles)
   │
   ▼
チャート画像を描く (320×180 RGB, 明るい背景)
   │
   ▼
光受容細胞へ入力 (R1–R6: 輝度, R8: 青/緑)
   │
   ▼
コネクトーム LIF シミュレーション（観測ごとに神経時間 0.5 秒）
   │
   ├──▶ 読み出し: 接近側 − 回避側 の発火率 → APPROACH / AVOID / NONE
   │
   └──▶ キノコ体 KC→MBON の重み（報酬学習で変わる唯一の場所）
              ▲
              │ 決済が確定した回だけ、確定損益 → PAM11（報酬）/ PPL101（嫌悪）
              │
檻 (決定的コード): 方向を受け取り、数量・価格・上限・諦めを agent.yaml で決めて発注する
```

### 3.1 入力（見せるもの）

- 直近の15分足（本数は `agent.yaml` で決める。目安は2時間〜1日）
- 通貨ペア、現在の売り気配・買い気配
- **含めないもの**：残高、損益、保有量。ハエに「自分の懐」を見せない
  （Stonkfly と同じ方針。報酬と視覚を分離しておかないと学習の解釈ができない）

### 3.2 シミュレーション

- ニューロンモデル：LIF。パラメータは Stonkfly / Shiu ら (2024) を初期値にする
- 観測ごとに神経時間 0.5 秒。15分間隔なら計算時間は問題にならない
- 配線図：**MaleCNS v1.0**（Stonkfly と同じ）。2026-09-16 に人間が選定し、
  ライセンスも同日 CC BY 4.0 と一次確認した
  （[`CONNECTOME_SURVEY.md`](CONNECTOME_SURVEY.md) 3.2・6.3）
- エッジ数は**シナプス数の閾値で桁が動く**（閾値なしで 25.6M、3 以上で 10.5M、
  5 以上で 6.2M）。閾値はモデルの選択であってデータの性質ではない。決めたら
  `agent.yaml` に置く
- 切り出しの範囲は性能を測ってから決める。ただし**キノコ体だけの切り出しは採れない。**
  視覚入力が KC に届く経路が切れるため（同 2.3 章）

### 3.3 読み出し（方向への変換）

ハエの脳が自前で持っている判断は、ほぼ「近づくか、逃げるか、動かないか」である。
キノコ体の学習も「この刺激には近づく／避ける」を報酬で書き換える仕組みなので、
これをそのまま売買の方向に写す。

| ハエの行動   | 使う回路（候補）                                              | 建玉なし   | 建玉あり   |
| ------------ | ------------------------------------------------------------- | ---------- | ---------- |
| `APPROACH`   | 接近・定位に関わる下行性ニューロン、キノコ体の接近側 MBON     | 買う       | 上限まで買い増す。上限なら持ち続ける |
| `AVOID`      | 迫る物体への逃避回路（LC4 / LPLC2 → 巨大線維 DNp01）、回避側 MBON | 何もしない | 全量売る   |
| `NONE`       | 両方とも閾値未満                                              | 何もしない | 持ち続ける |

- 読み出しは「接近の指標 − 回避の指標」の1本の軸。正の閾値を超えたら `APPROACH`、
  負の閾値を下回ったら `AVOID`、間は `NONE`
- 閾値・対象ニューロン群・神経時間は `agent.yaml` に置く。**ハエが自分で書き換えない**
- Stonkfly は左右 DNp20 の発火率差（回転）を売買に読み替えているが、
  ドパバエは**接近／回避の回路をその意味のまま使う**。読み替えの恣意性を小さくするため。
  **これは設計者の選択であり、検証されていない。** Stonkfly が「回転の癖が買い癖になる」と
  警告しているのと同じ危険が、接近／回避の読み出しにもある
- それでもこれは設計者が決めた読み替えであり、「ハエの脳に売買を判断する細胞がある」
  という意味ではない。記録にもそう書く
- **現物のみ**なので、建玉なしの `AVOID` は結果として何もしない。
  ただし記録には `AVOID` と残す（評価で `NONE` と区別する）

### 3.4 檻（決定的コード）

ハエは方向しか出さない。以下はすべて `agent.yaml` の値で決定的コードが決める。

| 項目           | 決めかた                                                       |
| -------------- | -------------------------------------------------------------- |
| 1回の買い金額  | 固定額（初期資金の一定割合）                                   |
| 建玉上限       | 取得原価合計の上限、現金比率の下限                             |
| 買いの間隔     | 約定後のクールダウン、1日の上限回数                            |
| 注文の形       | 指値（現在の買い気配）。次回までに約定しなければ取り消す       |
| 諦め           | 保有上限日数、ドローダウン停止（新規買い停止）、強制手仕舞い   |
| 判断できないとき | HOLD（シミュレーション失敗、画像欠損、データが古い、取引所異常） |

ハエが毎回 `APPROACH` と言い続けても、檻の中で階段状に積み上がって上限で止まる。
毎回 `AVOID` と言い続ければ、何も持たないまま終わる。どちらも最悪ケースは
ナンピノニクスと同じ範囲に収まる。

### 3.5 報酬学習

Stonkfly の設計を出発点にし、次の点を変える。

| 項目           | Stonkfly                                   | ドパバエ                                           |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| 報酬のタイミング | 観測ごと（含み損益込み）                  | **決済が確定した回だけ**                           |
| 報酬の閾値     | ±0.01 USDC                                 | 手数料より十分大きい値（`agent.yaml`）             |
| 報酬の対象     | PAM11（報酬 15 細胞）/ PPL101（嫌悪 2 細胞） | 同じ細胞群から始める                             |
| 可塑性の場所   | KC→MBON07 / MBON11                         | 同じ                                               |
| 記憶の減衰     | 1,800 秒                                   | 運用スケール（日〜週）に伸ばす。**未検証の拡張**   |
| 学習ルール     | anti-Hebbian（抑圧のみ）                   | まずは同じ。抑圧のみだと「何もしない」に寄るので観察対象 |

報酬の判定はペーパートレードの確定損益（`performance.py` 相当）から取る。
評価に含めるのは観測した値のみ。損益が取得できなかった回は報酬を出さず `null` を記録する。

実装の数値がそのまま性格になる。

- 報酬 15 細胞、嫌悪 2 細胞：喜びに敏感で、痛みに鈍い
- 抑圧のみ：ドパが出るたびに覚えるのは「その直前に見ていたものへの反応を弱める」こと。
  ドパが欲しくてトレードしているのに、覚えるのはやめかたばかり
- 記憶の減衰を伸ばしすぎると抑圧が溜まって何もしなくなる。ここは観察対象

### 3.6 記録

判断ログには、ナンピノニクスの項目に加えて次を残す。

- 見せた画像のハッシュと描画に使った足の範囲
- 読み出しに使ったニューロン群（接近側・回避側）の発火数と、方向の根拠
- ハエの答え（`APPROACH` / `AVOID` / `NONE`）と、檻がそれをどう扱ったか
  （買った／売った／上限で止めた／クールダウン中／HOLD）
- その回に与えたドーパミン刺激（なし / 報酬 / 嫌悪）と根拠になった損益
- シナプス重みのスナップショット（一定間隔）

ハエの反応は観測値なので、そのまま書く。解釈（「ハエが嫌がった」等）は
`narrate.py` 側の言語化に閉じ込め、判断ログには書かない。

## 4. 評価（Stonkfly に無い部分）

これが揃うまで「学んだ」とは言わない。

1. **重み固定版と学習版の並走**：同じ期間の15分足で、方向の判定がどう違うか
2. **未使用期間での検証**：学習に使っていない期間で同じ比較をする
3. **檻だけとの比較**：ハエなし（毎回 `APPROACH`）で檻だけ回したときとの成績差を見る
4. **ランダムとの比較**：同じ頻度でランダムに `APPROACH` / `AVOID` を出す対照群を置く

4 が一番重要。ハエの方向がランダムと区別できなければ、
ハエは「たまに買って、たまに売る乱数」と同じである。

固定版の段階で 4 を回し、ネットワークの偏り（いつも `APPROACH`、いつも `AVOID`）を
先に測る。Stonkfly が自分で警告している「回転の癖が買い癖になる」をここで捕まえる。

## 5. 実装順序（案）

1. 檻（決定的コード）と方向インタフェース。ナンピノニクスの `cli` / `observe` /
   `orders` / `journal` / `run` を流用し、`decide.py` を「方向を受け取って
   数量・価格・上限・諦めを決める」形に置き換える。
   この段階の方向の出どころは「常時 `APPROACH`」と「ランダム」（評価用）
2. チャート描画と光受容細胞へのマッピング（Stonkfly の `docs/model.md` を参照）
3. 重み固定のシミュレーションで `APPROACH` / `AVOID` / `NONE` を返す。**まずは学習なし**
4. 評価 1・3・4 を回し、固定版の挙動と偏りを記録する
5. 可塑性と報酬を足す
6. 評価 1〜4 を回す

学習を最後にするのは、「学習の効果」と「読み出しの偏り」を分けて見るため。

## 6. 決めていないこと

- キャラクター設定（ナンピノニクスの `character-design.yaml` の型で決める）
- 配線図のデータソースとライセンスの確認
- 読み出しに使うニューロン群（接近側・回避側それぞれ。候補は 3.3 節）
- 記憶の減衰を伸ばしたときに、抑圧のみの学習ルールが破綻しないか
- 全脳を回す計算資源をどこに置くか（定期実行の環境に 16 GB 級が要る）
- シナプス数の閾値（3.2 節）
- 静止発火率の扱い。光受容細胞は抑制性（ヒスタミン）しか出さないため、
  全ニューロンが静止していると「光が当たる」が「脱抑制」として現れる
- 買い気配と売り気配の線が重なったときの扱い。スプレッドが 1 円だと同じ画素の行に落ち、
  あとから描いた側だけが残る。青が消えると R8 への入力が失われる
  （[`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) Phase 2 後半）
- 文字（ペア名と気配の数字）を見せるかどうか。ハエは読めないが画素としては入力される
- 信用取引（売りから入る `AVOID`）。`bitbank paper` が現物のみのため当面扱わない。
  CLI 側への改善要望は別途出す
