# 設計メモ — ハエ脳エージェント（仮称：フライ個体）

> **この文書の役割**：本リポジトリで開発する個体（ナンピノニクスを型にした
> **別個体**）の設計メモ。**作業指示ではない。** 本リポジトリの実装範囲は
> [`REPOSITORY_PLAN.md`](REPOSITORY_PLAN.md) にのみ定義され、
> 実装の順序は [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md) が正である。
> 本書はナンピノニクスのリポジトリ
> （`tjackiet/ai-agent-farm-nampinonychus` の `docs/FLY_AGENT_DESIGN_MEMO.md`）
> から持ち込んだ下書きであり、持ち込み元は参照のみで変更しない。
> 本書に書かれていても、`REPOSITORY_PLAN.md` の「扱わないもの」にあるものは実装しない。
> 本文中の「フライ個体」は、2026-09-15 に「ドパバエ」（Dopabae）と命名された。
> 参考にした外部プロジェクト：
> [nftechie/stonkfly](https://github.com/nftechie/stonkfly)（MaleCNS v1.0 を使った試み）。

## 1. 何をする個体か

ショウジョウバエのコネクトーム（配線図）を LIF ニューロンで動かし、
**15分足のチャート画像を「目」に見せ**、その反応を売買判断の一部に使う。

ただし、ハエ脳が持つのは **買いを止める権利だけ**（ナンピノニクスの
`veto.py` と同じ位置）。売買本体は決定的コードが担い、ハエの反応が
どうであれ最悪ケース（どこまで買い下がるか、どこで撤退するか）は変わらない。

これは「ハエの脳を取引システムに繋ぐ実験」であり、
**儲かることを目的にしない。** 目的は次の2つ。

1. ハエ脳の反応が、決定的コードの判断に対して何らかの偏りを持つか観察する
2. 報酬学習（ドーパミンによる可塑性）を足したとき、挙動がどう変わるか観察する

## 2. ナンピノニクスから持ち出すもの・変えるもの

| 項目               | ナンピノニクス                         | フライ個体                                          |
| ------------------ | -------------------------------------- | --------------------------------------------------- |
| 発注・市場データ   | `bitbank-lab-cli`（paper）             | **同じ**                                            |
| 実行間隔           | 15分                                   | **同じ**                                            |
| 売買本体           | アンカー基準のナンピン階段（`decide.py`） | **同じ**（まずは丸ごと流用）                      |
| 拒否権の主体       | LLM（`veto.py`）                       | **ハエ脳**（`veto.py` と同じ二値インタフェース）    |
| 拒否権の答え       | `STOP` / `PROCEED`                     | **同じ**                                            |
| 呼べないときの扱い | `veto.on_failure: hold`                | **同じ**（シミュレーション失敗・入力欠損は HOLD）  |
| 記録の言語化       | LLM（`narrate.py`）                    | 同じ（ハエの反応の説明を追加）                      |
| 数値の正           | `agent.yaml`                           | **同じ**。学習で動くのはシナプス重みのみ            |
| 実取引             | しない                                 | **しない**（Stonkfly の live モードは持ち込まない） |

CLAUDE.md の不変ルール（ペーパーのみ、迷ったら HOLD、値を自分で書き換えない、
観測していない値を書かない、秘密情報を残さない）は**そのまま引き継ぐ**。

## 3. 構成

```
15分足 (bitbank candles)
   │
   ▼
チャート画像を描く (320×180 RGB, 明るい背景)
   │
   ▼
光受容細胞へ入力 (R1–R6: 輝度, R8: 青/緑)
   │
   ▼
コネクトーム LIF シミュレーション（観測ごとに神経時間 0.5 秒）
   │
   ├──▶ 読み出し: 下行性ニューロンの発火率 → STOP / PROCEED
   │
   └──▶ キノコ体 KC→MBON の重み（報酬学習で変わる唯一の場所）

決定的コード (decide.py) が BUY を出した回だけ、STOP / PROCEED を諮る
```

### 3.1 入力（見せるもの）

- 直近の15分足（本数は `agent.yaml` で決める。目安は2時間〜1日）
- 通貨ペア、現在の売り気配・買い気配
- **含めないもの**：残高、損益、保有量。ハエに「自分の懐」を見せない
  （Stonkfly と同じ方針。報酬と視覚を分離しておかないと学習の解釈ができない）

### 3.2 シミュレーション

- ニューロンモデル：LIF。パラメータは Stonkfly / Shiu ら (2024) を初期値にする
- 観測ごとに神経時間 0.5 秒。15分間隔なら計算時間は問題にならない
- 配線図：MaleCNS v1.0（Stonkfly と同じ）か FlyWire。どちらにするかは
  可塑性を入れるキノコ体まわりのアノテーションが揃っている方を選ぶ
- 全脳を回すか、キノコ体まわりだけ切り出すかは**性能を測ってから決める**
  （全脳は 16 GB 級のメモリが要る）

### 3.3 読み出し（拒否権への変換）

- Stonkfly は左右 DNp20 の発火率差と DNpe017 の発火で三値に落としている
- フライ個体では**二値**にする：
  - 「回避側」と定めた指標が閾値を超えたら `STOP`
  - それ以外は `PROCEED`
- 閾値・対象ニューロン・神経時間は `agent.yaml` に置く。**ハエが自分で書き換えない**
- これは設計者が決めた読み替えであり、「ハエの脳に売買を判断する細胞がある」
  という意味ではない。記録にもそう書く

### 3.4 報酬学習

Stonkfly の設計を出発点にし、次の点を変える。

| 項目           | Stonkfly                                   | フライ個体                                         |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| 報酬のタイミング | 観測ごと（含み損益込み）                  | **決済が確定した回だけ**                           |
| 報酬の閾値     | ±0.01 USDC                                 | 手数料より十分大きい値（`agent.yaml`）             |
| 報酬の対象     | PAM11（報酬 15 細胞）/ PPL101（嫌悪 2 細胞） | 同じ細胞群から始める                             |
| 可塑性の場所   | KC→MBON07 / MBON11                         | 同じ                                               |
| 記憶の減衰     | 1,800 秒                                   | 運用スケール（日〜週）に伸ばす。**未検証の拡張**   |
| 学習ルール     | anti-Hebbian（抑圧のみ）                   | まずは同じ。抑圧のみだと「何もしない」に寄るので観察対象 |

報酬の判定はペーパートレードの確定損益（`performance.py` 相当）から取る。
評価に含めるのは観測した値のみ。損益が取得できなかった回は報酬を出さず `null` を記録する。

### 3.5 記録

判断ログには、ナンピノニクスの項目に加えて次を残す。

- 見せた画像のハッシュと描画に使った足の範囲
- 読み出しに使ったニューロン群の発火数と、`STOP` / `PROCEED` の根拠
- その回に与えたドーパミン刺激（なし / 報酬 / 嫌悪）と根拠になった損益
- シナプス重みのスナップショット（一定間隔）

ハエの反応は観測値なので、そのまま書く。解釈（「ハエが嫌がった」等）は
`narrate.py` 側の言語化に閉じ込め、判断ログには書かない。

## 4. 評価（Stonkfly に無い部分）

これが揃うまで「学んだ」とは言わない。

1. **重み固定版と学習版の並走**：同じ期間の15分足で、拒否権の判定がどう違うか
2. **未使用期間での検証**：学習に使っていない期間で同じ比較をする
3. **ハエ無しとの比較**：ナンピノニクス本体（拒否権なし）との成績差を見る
4. **ランダム拒否権との比較**：同じ頻度でランダムに `STOP` を出す対照群を置く

4 が一番重要。ハエの拒否権がランダムと区別できなければ、
ハエは「たまに買いを止める乱数」と同じである。

## 5. 実装順序（案）

1. ナンピノニクスの `veto.py` を、外部プロセスの二値応答を受ける形に抽象化する
   （この段階では LLM もハエも同じインタフェース）
2. チャート描画と光受容細胞へのマッピング（Stonkfly の `docs/model.md` を参照）
3. 重み固定のシミュレーションで `STOP` / `PROCEED` を返す。**まずは学習なし**
4. 評価 1・3・4 を回し、固定版の挙動を記録する
5. 可塑性と報酬を足す
6. 評価 1〜4 を回す

学習を最後にするのは、「学習の効果」と「読み出しの偏り」を分けて見るため。

## 6. 決めていないこと

- 個体の名前・キャラクター設定（ナンピノニクスの `character-design.yaml` の型で決める）
- 配線図のデータソースとライセンスの確認
- 読み出しに使うニューロン群（Stonkfly の DNp20 をそのまま使うか）
- 記憶の減衰を伸ばしたときに、抑圧のみの学習ルールが破綻しないか
- 全脳を回す計算資源をどこに置くか（定期実行の環境に 16 GB 級が要る）
