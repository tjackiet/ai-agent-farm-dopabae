## 1. このリポジトリの目的

このリポジトリでは、AIエージェントファームの2体目の試験エージェント
「ドパバエ」（Dopabae）を開発する。

ショウジョウバエのコネクトームを LIF ニューロンで動かし、15分足のチャート画像を
「目」に見せて、その反応を**買いを止める権利**にだけ使う。売買本体は決定的コードが担い、
ペーパートレードによるフォワード運用を行う。**実取引は行わない。**

儲けることが目的ではない。目的は次の2つ（設計メモ 1 章）。

1. ハエ脳の反応が、決定的コードの判断に対して何らかの偏りを持つか観察する
2. 報酬学習（ドーパミンによる可塑性）を足したとき、挙動がどう変わるか観察する

## 4. 責務の分離

以下の責務を混同しない。

### 売買本体（決定的コード）

ナンピノニクスの `decide.py` 相当。観測と状態から BUY・SELL・HOLD を決める純関数。
ハエの反応がどうであれ、最悪ケース（どこまで買い下がるか、どこで撤退するか）は
ここで決まり、変わらない。

### 拒否権（二値インタフェース）

決定的コードが BUY を出した回だけ諮る。答えは `STOP` / `PROCEED` の二値。
Phase 1 では LLM もハエも同じインタフェースで差し替えられる形にする。
呼べなかった・答えを読めなかったときは `veto.on_failure`（既定 `hold`）に従う。

### ハエ脳（シミュレーション）

チャート画像を受け取り、LIF シミュレーションを回し、読み出し用ニューロン群の
発火数を返す。**ここは売買を知らない。** 残高・損益・保有量は見せない。

### 読み出し（発火率 → STOP / PROCEED）

設計者が決めた読み替え。閾値・対象ニューロン・神経時間は `agent.yaml` に置く。
ハエが書き換えない。「ハエの脳に売買を判断する細胞がある」という意味ではない。

### 報酬と可塑性

決済が確定した回だけ、確定損益から報酬（PAM11）/ 嫌悪（PPL101）の刺激を決める。
変わるのは KC→MBON のシナプス重みだけ。報酬の閾値は `agent.yaml`。

### 評価

固定版・学習版・ハエ無し・ランダム拒否権を同じ物差しで比べる。
これが揃うまで「学んだ」とは言わない（設計メモ 4 章）。

### Phase 1：拒否権の二値インタフェース抽象化

ナンピノニクスの売買本体（`config` / `cli` / `observe` / `state` / `decide` /
`orders` / `journal` / `run` と `veto`）を本リポジトリへ**コピーして**持ち込み、
`veto` を「外部の判定器から二値の応答を受ける」形に抽象化する。

#### 決めたこと

| 項目             | 決定                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| 持ち込み方       | コピー。共通ライブラリ化しない（`REPOSITORY_PLAN.md`「扱わないもの」2） |
| 判定器の契約     | 入力：観測（画像または事実）／ 出力：`STOP` か `PROCEED` の二値と根拠 |
| 最初の判定器     | 「常時 `PROCEED`」と「ナンピノニクスと同じ LLM 版」の2つ。ハエ版はまだ作らない |
| 失敗時           | `veto.on_failure`（既定 `hold`）。判定器の種類によらず同じ            |
| 諮る回           | `action` が BUY の回だけ。売り・時間切れ・強制手仕舞い・冬眠の取消は諮らない |
| 止めた回         | 取消も発注もしない。板の状態を変えないまま次の回へ持ち越す            |

#### 完了の目安

- 判定器を `agent.yaml` の `veto.backend` で切り替えられる
- 「常時 `PROCEED`」でナンピノニクスと同じ判断が出る（回帰）
- 判断ログの `veto` に、判定器の種類・答え・根拠・失敗理由が残る（諮らなかった回は `null`）

### Phase 2：チャート描画と光受容細胞へのマッピング

Stonkfly の `docs/model.md`「What the fly sees」を参照して、15分足から
チャート画像を描き、光受容細胞への入力に変換する。

#### 決めたこと

| 項目             | 決定                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| 画像             | 320×180 RGB、明るい背景（Stonkfly と同じ。暗い背景では KC がほぼ発火しなかったため） |
| 見せるもの       | 直近の15分足（本数は `agent.yaml`。目安は2時間〜1日）、通貨ペア、売り気配・買い気配 |
| 見せないもの     | 残高・損益・保有量                                                       |
| 入力先           | R1–R6：輝度（線形 sRGB）、R8：青／緑の代理値                              |
| マッピングの根拠 | 配線図側のカラム注釈から推定（Stonkfly の方法）。**配線図の選定（3 節 4）が終わるまで着手できない** |
| 記録             | 画像のハッシュと描画に使った足の範囲を判断ログに残す                      |

#### 完了の目安

- 同じ足を与えれば同じ画像（同じハッシュ）が出る
- 画像から入力配列（受容細胞 ID → 電流）が作れる。未マッピングの受容細胞に値を作らない
- 描画に失敗した回は入力を作らず、上位が HOLD できる

### Phase 3：重み固定のシミュレーションで STOP / PROCEED

コネクトームを LIF で動かし、読み出し用ニューロン群の発火数から二値を返す判定器を作る。
**学習は入れない。**

#### 決めたこと

| 項目             | 決定                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| ニューロンモデル | LIF。パラメータは Stonkfly / Shiu ら (2024) を初期値にする              |
| 神経時間         | 観測ごとに 0.5 秒（`agent.yaml`）                                       |
| 読み出し         | 「回避側」と定めた指標が閾値を超えたら `STOP`、それ以外は `PROCEED`     |
| 対象ニューロン   | Stonkfly の DNp20 / DNpe017 を出発点にするかは**未決**（設計メモ 6 章）。`agent.yaml` に置く |
| 全脳か部分か     | 性能を測ってから決める。定期実行の環境で回らないなら部分切り出しを検討する |
| 失敗時           | シミュレーション失敗・入力欠損は判定器の失敗として扱い、`veto.on_failure` に従う |

#### 完了の目安

- ハエ版の判定器が Phase 1 の契約を満たし、`veto.backend` で切り替えられる
- 判断ログに、読み出しに使ったニューロン群の発火数と `STOP` / `PROCEED` の根拠が残る
- 1回の観測が `runtime.max_runtime_sec` に収まる（収まらなければ部分切り出しへ）

### Phase 4：評価（固定版）

設計メモ 4 章の評価 1・3・4 を回し、固定版の挙動を記録する。

| 評価 | 内容                                                     | 本 Phase |
| ---- | -------------------------------------------------------- | -------- |
| 1    | 重み固定版と学習版の並走                                 | 固定版の記録だけ取る（学習版は Phase 6） |
| 3    | ハエ無し（拒否権なし）との比較                           | 回す     |
| 4    | 同じ頻度でランダムに `STOP` を出す対照群との比較         | **回す（最重要）** |

#### 決めたこと

- 評価は同じ期間の15分足で行い、成績の物差しはナンピノニクスの `performance.py` 相当
  （総資産の推移・ドローダウン・Buy&Hold 比較）を流用する
- ランダム拒否権の `STOP` 頻度は、固定版が同じ期間に出した `STOP` の頻度に合わせる
- 儲かったかではなく、**ランダムと区別できるか**を見る

#### 完了の目安

- 評価 3・4 の結果と、固定版の判定の記録が `docs/` または `records/` に残る
- ハエの拒否権がランダムと区別できるかの所見が書ける（区別できなくてもよい。それも結果）

### Phase 5：可塑性と報酬

Stonkfly の設計を出発点に、決済が確定した回だけ報酬を出す。

#### 決めたこと

| 項目             | Stonkfly                                     | 本リポジトリ                                       |
| ---------------- | -------------------------------------------- | -------------------------------------------------- |
| 報酬のタイミング | 観測ごと（含み損益込み）                     | **決済が確定した回だけ**                           |
| 報酬の閾値       | ±0.01 USDC                                   | 手数料より十分大きい値（`agent.yaml`）             |
| 報酬の対象       | PAM11（報酬 15 細胞）/ PPL101（嫌悪 2 細胞） | 同じ細胞群から始める                               |
| 可塑性の場所     | KC→MBON07 / MBON11                           | 同じ                                               |
| 記憶の減衰       | 1,800 秒                                     | 運用スケール（日〜週）に伸ばす。**未検証の拡張**   |
| 学習ルール       | anti-Hebbian（抑圧のみ）                     | まずは同じ。「何もしない」に寄るかは観察対象       |

- 報酬の判定はペーパートレードの確定損益から取る。損益が取得できなかった回は
  報酬を出さず `null` を記録する
- 学習で変わるのはシナプス重みだけ。閾値・対象ニューロン・報酬の閾値は
  `agent.yaml` に置き、ハエが書き換えない（`CLAUDE.md`）
- 記憶の減衰を伸ばしたときに抑圧のみのルールが破綻しないかは、本 Phase で観察する

#### 完了の目安

- 判断ログに、その回に与えたドーパミン刺激（なし / 報酬 / 嫌悪）と根拠の損益が残る
- シナプス重みのスナップショットが一定間隔で保存される（Git 管理外）
- 重みをリセットすれば固定版と同じ判定に戻る

## 6. 定期運用と記録

Phase 3 以降は、ナンピノニクスと同じく15分ごとの定期実行で回す。
ただし 3 節の前提（計算資源）が確認できるまでは、手で1回ずつ実行する。

判断ログには、ナンピノニクスの項目に加えて次を残す（設計メモ 3.5 節）。

- 見せた画像のハッシュと描画に使った足の範囲
- 読み出しに使ったニューロン群の発火数と、`STOP` / `PROCEED` の根拠
- その回に与えたドーパミン刺激（なし / 報酬 / 嫌悪）と根拠になった損益
- シナプス重みのスナップショット（一定間隔）

ハエの反応は観測値なので、そのまま書く。解釈は記録の言語化に閉じ込め、
判断ログには書かない。
