## 1. このリポジトリの目的

このリポジトリでは、AIエージェントファームの2体目の試験エージェント
「ドパバエ」（Dopabae）を開発する。

ショウジョウバエのコネクトームを LIF ニューロンで動かし、15分足のチャート画像を
「目」に見せて、その反応を売買の**方向**（近づく／逃げる／どちらでもない）に使う。
数量・価格・上限・諦めは決定的コード（檻）が担い、ペーパートレードで運用する。
**実取引は行わない。現物のみを扱う。**

儲けることが目的ではない。目的は次の2つ（設計メモ 1 章）。

1. 重み固定のハエの反応が、ランダムと区別できる偏りを持つか観察する
2. 報酬学習（ドーパミンによる可塑性）を足したとき、挙動がどう変わるか観察する

## 4. 責務の分離

以下の責務を混同しない。

### ハエ脳（シミュレーション）

チャート画像を受け取り、LIF シミュレーションを回し、接近側・回避側の
ニューロン群の発火数を返す。**ここは売買を知らない。** 残高・損益・保有量は見せない。

### 読み出し（発火率 → 方向）

「接近の指標 − 回避の指標」の1本の軸を閾値で三値（`APPROACH` / `AVOID` / `NONE`）に
落とす。設計者が決めた読み替え。閾値・対象ニューロン・神経時間は `agent.yaml` に置く。
ハエが書き換えない。「ハエの脳に売買を判断する細胞がある」という意味ではない。

### 方向の出どころ（`direction.source`）

方向を返すものは差し替えられる。ハエ版のほかに、評価用の「常時 `APPROACH`」と
「ランダム」を持つ。どれも同じ契約（入力：観測、出力：方向と根拠）を満たす。
返せなかった・読めなかったときは `direction.on_failure`（既定 `hold`）に従う。

### 檻（決定的コード）

方向を受け取り、数量・価格・建玉上限・現金比率・クールダウン・保有上限・
ドローダウン停止を `agent.yaml` の値で決めて、取消と発注を組み立てる純関数。
ハエがどう答えても最悪ケースはここで決まる。I/O を持たない。

### 報酬と可塑性

決済が確定した回だけ、確定損益から報酬（PAM11）/ 嫌悪（PPL101）の刺激を決める。
変わるのは KC→MBON のシナプス重みだけ。報酬の閾値は `agent.yaml`。

### 評価

固定版・学習版・檻だけ・ランダムを同じ物差しで比べる。
これが揃うまで「学んだ」とは言わない（設計メモ 4 章）。

### Phase 1：檻と方向インタフェース

ナンピノニクスの `config` / `cli` / `observe` / `state` / `orders` / `journal` / `run` を
本リポジトリへ**コピーして**持ち込み、`decide.py` を檻に置き換える。
ナンピノニクスの `veto.py` は持ち込まない。

#### 決めたこと

| 項目             | 決定                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| 持ち込み方       | コピー。共通ライブラリ化しない（`REPOSITORY_PLAN.md`「扱わないもの」2） |
| 方向の契約       | 入力：観測（画像または事実）／ 出力：`APPROACH` / `AVOID` / `NONE` と根拠 |
| 最初の出どころ   | 「常時 `APPROACH`」と「ランダム」（`agent.yaml` の `direction.source`）。ハエ版は Phase 3 |
| 失敗時           | `direction.on_failure`（既定 `hold`）。出どころの種類によらず同じ     |
| 檻の入力         | 方向、観測、現在状態。出力は「何を取り消し、何を発注し、なぜそうしたか」 |
| 買い             | `APPROACH` かつ建玉が上限未満かつクールダウン外のとき、固定額の指値を買い気配に置く |
| 売り             | `AVOID` かつ建玉ありのとき、全量を指値で売り気配に置く。時間切れ・強制手仕舞いは方向によらず檻が出す |
| 未約定の指値     | 次回までに約定しなければ取り消す。二重発注しないため、本数は `paper active-orders` から数える |
| 現物のみ         | 建玉なしの `AVOID` は何もしない。記録には `AVOID` と残す              |
| LLM              | 記録の言語化（`narrate.py`）だけ。売買には関与しない                  |

#### 完了の目安

- 方向の出どころを `direction.source` で切り替えられる
- 「常時 `APPROACH`」で、檻の上限・クールダウン・諦めがテストで担保される
  （建玉上限で止まる、現金比率を割らない、時間切れで手仕舞う、ドローダウンで新規買いが止まる）
- 判断ログの `direction` に、出どころの種類・答え・根拠・失敗理由と、
  檻がそれをどう扱ったかが残る

### Phase 2：チャート描画と光受容細胞へのマッピング

Stonkfly の `docs/model.md`「What the fly sees」を参照して、15分足から
チャート画像を描き、光受容細胞への入力に変換する。

#### 決めたこと

| 項目             | 決定                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| 画像             | 320×180 RGB、明るい背景（Stonkfly と同じ。暗い背景では KC がほぼ発火しなかったため） |
| 見せるもの       | 直近の15分足（本数は `agent.yaml`。目安は2時間〜1日）、通貨ペア、売り気配・買い気配 |
| 見せないもの     | 残高・損益・保有量                                                       |
| 入力先           | R1–R6：輝度（線形 sRGB）、R8：青／緑の代理値                              |
| マッピングの根拠 | 配線図側のカラム注釈から推定（Stonkfly の方法）。**配線図の選定（3 節 4）が終わるまで着手できない** |
| 記録             | 画像のハッシュと描画に使った足の範囲を判断ログに残す                      |

#### 完了の目安

- 同じ足を与えれば同じ画像（同じハッシュ）が出る
- 画像から入力配列（受容細胞 ID → 電流）が作れる。未マッピングの受容細胞に値を作らない
- 描画に失敗した回は入力を作らず、上位が HOLD できる

### Phase 3：重み固定のシミュレーションで方向を返す

コネクトームを LIF で動かし、接近側・回避側のニューロン群の発火数から
方向を返す出どころ（ハエ版）を作る。**学習は入れない。**

#### 決めたこと

| 項目             | 決定                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| ニューロンモデル | LIF。パラメータは Stonkfly / Shiu ら (2024) を初期値にする              |
| 神経時間         | 観測ごとに 0.5 秒（`agent.yaml`）                                       |
| 読み出し         | 接近の指標 − 回避の指標。正の閾値超で `APPROACH`、負の閾値未満で `AVOID`、間は `NONE` |
| 対象ニューロン   | 接近側・回避側それぞれ**未決**（候補は設計メモ 3.3 節）。`agent.yaml` に置く |
| 全脳か部分か     | 性能を測ってから決める。定期実行の環境で回らないなら部分切り出しを検討する |
| 失敗時           | シミュレーション失敗・入力欠損は出どころの失敗として扱い、`direction.on_failure` に従う |

#### 完了の目安

- ハエ版が Phase 1 の契約を満たし、`direction.source` で切り替えられる
- 判断ログに、接近側・回避側の発火数と方向の根拠が残る
- 1回の観測が `runtime.max_runtime_sec` に収まる（収まらなければ部分切り出しへ）

### Phase 4：評価（固定版）

設計メモ 4 章の評価 1・3・4 を回し、固定版の挙動と偏りを記録する。

| 評価 | 内容                                                     | 本 Phase |
| ---- | -------------------------------------------------------- | -------- |
| 1    | 重み固定版と学習版の並走                                 | 固定版の記録だけ取る（学習版は Phase 6） |
| 3    | 檻だけ（常時 `APPROACH`）との比較                        | 回す     |
| 4    | 同じ頻度でランダムに `APPROACH` / `AVOID` を出す対照群との比較 | **回す（最重要）** |

#### 決めたこと

- 評価は同じ期間の15分足で行い、成績の物差しはナンピノニクスの `performance.py` 相当
  （総資産の推移・ドローダウン・Buy&Hold 比較）を流用する
- ランダムの `APPROACH` / `AVOID` / `NONE` の頻度は、固定版が同じ期間に出した頻度に合わせる
- 固定版の偏り（いつも `APPROACH`、いつも `AVOID`）を先に測る。
  偏りがあれば、それは市場の洞察ではなくネットワークの癖として記録する
- 儲かったかではなく、**ランダムと区別できるか**を見る

#### 完了の目安

- 評価 3・4 の結果と、固定版の方向の記録が `docs/` または `records/` に残る
- ハエの方向がランダムと区別できるかの所見が書ける（区別できなくてもよい。それも結果）

### Phase 5：可塑性と報酬

Stonkfly の設計を出発点に、決済が確定した回だけ報酬を出す。

#### 決めたこと

| 項目             | Stonkfly                                     | 本リポジトリ                                       |
| ---------------- | -------------------------------------------- | -------------------------------------------------- |
| 報酬のタイミング | 観測ごと（含み損益込み）                     | **決済が確定した回だけ**                           |
| 報酬の閾値       | ±0.01 USDC                                   | 手数料より十分大きい値（`agent.yaml`）             |
| 報酬の対象       | PAM11（報酬 15 細胞）/ PPL101（嫌悪 2 細胞） | 同じ細胞群から始める                               |
| 可塑性の場所     | KC→MBON07 / MBON11                           | 同じ                                               |
| 記憶の減衰       | 1,800 秒                                     | 運用スケール（日〜週）に伸ばす。**未検証の拡張**   |
| 学習ルール       | anti-Hebbian（抑圧のみ）                     | まずは同じ。「何もしない」に寄るかは観察対象       |

- 報酬の判定はペーパートレードの確定損益から取る。損益が取得できなかった回は
  報酬を出さず `null` を記録する
- 学習で変わるのはシナプス重みだけ。閾値・対象ニューロン・報酬の閾値は
  `agent.yaml` に置き、ハエが書き換えない（`CLAUDE.md`）
- 記憶の減衰を伸ばしたときに抑圧のみのルールが破綻しないかは、本 Phase で観察する

#### 完了の目安

- 判断ログに、その回に与えたドーパミン刺激（なし / 報酬 / 嫌悪）と根拠の損益が残る
- シナプス重みのスナップショットが一定間隔で保存される（Git 管理外）
- 重みをリセットすれば固定版と同じ方向に戻る

## 6. 定期運用と記録

Phase 3 以降は、ナンピノニクスと同じく15分ごとの定期実行で回す。
ただし 3 節の前提（計算資源）が確認できるまでは、手で1回ずつ実行する。

判断ログには、ナンピノニクスの項目に加えて次を残す（設計メモ 3.6 節）。

- 見せた画像のハッシュと描画に使った足の範囲
- 接近側・回避側のニューロン群の発火数と、方向の根拠
- ハエの答えと、檻がそれをどう扱ったか
- その回に与えたドーパミン刺激（なし / 報酬 / 嫌悪）と根拠になった損益
- シナプス重みのスナップショット（一定間隔）

ハエの反応は観測値なので、そのまま書く。解釈は記録の言語化に閉じ込め、
判断ログには書かない。
